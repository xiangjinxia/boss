# IDEA 运行与答辩指南

## 运行前准备

1. 安装 JDK 21、Node 22.12+ / 24、MySQL 8 和 IDEA，确保 `java -version`、`node -v` 正常。
2. 执行 scripts/create-database.sql 建空库，IDEA 打开 backend/pom.xml。
3. IDEA Project SDK 与 Maven Runner JRE 都选择 JDK 21。设置 DB_PORT=3306、DB_USER 和自己的 DB_PASSWORD；工作目录 backend。
4. 运行 CampusApplication；终端 frontend 内 `npm ci`、`npm run dev`。
5. 用三个浏览器环境（例如 Chrome、Edge、Chrome 无痕）分别登录 seller、buyer、admin。密码均为 Campus123!。

系统默认不校验真实学校身份，所以展示为“校园同学”仅表示课程学生账号，不能宣称经过学籍认证。

## 环境变量

| 名称 | 本地默认 | 用途 |
| --- | --- | --- |
| DB_HOST | 127.0.0.1 | 数据库主机 |
| DB_PORT | 3307 | Compose 映射端口，本机安装通常 3306 |
| DB_NAME | campus_exchange | 库名 |
| DB_USER | campus | MySQL 应用用户名 |
| DB_PASSWORD | campus-local | 仅 Compose 本地演示默认；自行安装须覆盖 |
| PORT | 8080 | 后端端口；改变后同步修改 Vite 代理 |
| UPLOAD_DIR | ./uploads | 可写图片目录，工作目录 backend |
| DEMO_DATA | true | 空库创建演示数据；共享部署关闭 |

敏感配置只在本机环境变量或忽略的 .env 中管理，不提交真实密码。前端开发地址和代理位于 vite.config.js。

## 常见问题

- **Access denied**：核对 IDEA 的 DB_USER、DB_PASSWORD 与 MySQL 账号授权；.env 不会自动注入 IDEA。
- **连接失败 / Communications link failure**：MySQL 是否运行，端口是 3306 还是 3307，库名是否创建。
- **Unsupported class version / release 21 not supported**：项目和 Maven 编译器均使用 JDK 21，不能只安装 Java 运行时。
- **Unknown database**：先运行 create-database.sql。Flyway 建表但不负责创建数据库。
- **Flyway checksum mismatch**：已运行的 V1 不要改动；新增 V2 迁移。课程空库要重建时先自行备份，勿在真实数据上直接清库。
- **已有表但缺 Flyway 历史**：推荐使用新的空库启动，避免手动导入与自动迁移混用。
- **前端没有商品**：看后端健康接口与浏览器 Network，确认 Vite 的代理端口对应后端。
- **图片不显示**：上传目录是否保留，工作目录是否固定，路径是否以 /uploads 或 /samples 开头并经代理。
- **登录角色混乱**：令牌在 sessionStorage；用不同浏览器或无痕窗口分开角色，同一标签页退出后再登录。
- **商品一直待审核**：使用 admin 在商品审核通过；编辑后必须重新审核。
- **订单不能直接完成**：先由卖家接受订单，再由买家确认；管理员不能代确认。
- **npm 提示 EBADENGINE**：使用 Node 22.12+ 或 24，不使用 Node 16/18。

## 答辩可能提问

1. **为什么不用真实支付？** 课程 V1.0 聚焦信息与履约闭环，订单记录的是线下交易，降低对接与资金处理成本。
2. **两个买家同时下单怎么办？** 待确认订单可以多条，卖家确认在事务中锁商品与订单，只允许一条确认；同时取消其他待确认订单，数据库唯一生成列进一步约束。
3. **前端隐藏按钮够安全吗？** 不够。Spring Security 控制登录/角色，Service 校验商品、买家和卖家归属，非法请求返回 403。
4. **为什么价格要快照？** 商品信息未来可能变化，订单应保留交易创建时的价格、名称和图片，统计基于订单金额。
5. **密码怎么保存？** BCrypt 单向哈希，不存明文；令牌只存 SHA-256 摘要，退出与封禁会撤销。
6. **怎么防恶意上传？** 限制大小、像素、文件数、扩展名、MIME、实际解码格式，重新编码、UUID 命名与上传归属校验。
7. **图表是否是假数据？** 由 SQL 对订单和商品聚合，历史演示订单是真实库表记录，接口验收把统计总量和订单明细交叉对照。
8. **如果后续改需求？** 前端页面组件、接口、业务 Service、数据库迁移分开；新字段用新迁移，已有测试回归检查交易规则。
