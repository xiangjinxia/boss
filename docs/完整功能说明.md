# 拾光校园二手交易平台——完整功能说明

版本：V1.1 · Vue 3 + Spring Boot + MySQL

本说明面向使用者和课程答辩，说明每个入口、操作步骤、状态变化和限制。项目代码保存在 https://github.com/xiangjinxia/boss 。数据库保存在你自己的 MySQL，上传图片保存在本机 backend/uploads；GitHub 中不包含你的本机数据库或个人上传图片。

## 1. 先理解整个系统

系统让学生把闲置商品发布到校园集市。管理员审核后，其他同学可以搜索、收藏、咨询和发起预约。卖家接受其中一位买家后，双方线下面交；买家确认完成后，可以对这次交易进行评价。

同一个学生账号既可以买东西，也可以卖东西，不用分别注册两种账号。管理员使用同一网站的管理后台入口。系统采用线下交易，不处理银行卡、微信或支付宝付款，也没有接入学校学籍认证。

| 角色 | 可以做什么 | 主要入口 |
| --- | --- | --- |
| 访客 | 浏览商品、搜索筛选、看公告、看卖家小铺和成交评价 | 校园集市、商品详情、卖家小铺 |
| 学生 | 发布、收藏、留言、预约、买卖订单、成交评价、举报、资料和通知 | 我的校园、发布闲置、留言消息、通知铃铛 |
| 管理员 | 审核商品、处理举报、管理用户、查询订单、维护分类公告、看统计和日志 | 管理后台 |

空库首次启动会生成演示账号：admin、seller、buyer，演示密码均为 Campus123!。它们分别便于演示管理员、卖家和买家。已有数据库升级不会重置账号密码，也不会重新生成演示数据。演示商品与历史订单为虚构样例，初始图片使用项目内原创插画，不代表真实实物照片。

## 2. 首页与寻找商品

### 2.1 公告

首页显示已发布的校园公告，置顶优先。点击标题弹出全文。草稿公告只有管理员可以查看。管理员保存发布、修改或删除公告后，用户重新进入或刷新首页即可看到结果。

### 2.2 为你发现 / 猜你喜欢

没有收藏偏好时显示“为你发现”，按真实收藏热度和发布时间排序。登录后有收藏记录时显示“猜你喜欢”，结合最近保留的最多 200 条收藏计算类别和价格偏好。

每张推荐卡片会给出实际理由，例如“与你收藏的教材书籍同类”“接近你的收藏价格”“有同学收藏”。展开“为什么推荐给我？”可以看评分方法、常收藏类别和参考价中位数。收藏或取消收藏后返回首页，或点击“更新推荐”，会重新计算。

| 个性化评分因素 | 满分 | 含义 |
| --- | --- | --- |
| 类别 | 45 | 该类别收藏数量 / 收藏最多类别数量 |
| 价格接近度 | 25 | 与收藏价格中位数越接近，得分越高 |
| 收藏热度 | 20 | 按真实收藏数对数归一化，10 次收藏达到此项上限 |
| 新鲜度 | 10 | 随发布时间逐渐衰减，7 天时为此项一半 |

价格项使用 max(0, 1 - abs(商品价格 - 参考价) / max(参考价, 1))；新鲜度使用 1 / (1 + 上架小时数 / 168)。无收藏时，收藏热度和新鲜度分别占 55、45 分。并列时按商品 ID 从新到旧排序。此处是可解释的规则推荐，没有宣称训练机器学习模型或验证推荐准确率。

推荐排除本人商品、已收藏商品、非在售商品及停用卖家的商品；未登录时无本人/已收藏排除条件。“同学们在收藏”单独按收藏数排序，可包含本人已经收藏的商品。收藏偏好可以参考已成交商品的历史价格。

当前推荐在内存中对符合条件的候选商品评分，适合课程演示规模。大规模部署应增加候选召回、缓存和效果评估。

### 2.3 校园集市

支持标题和描述关键词、分类、最低/最高价格、最近 1/7/30 天筛选；支持最新发布、价格升序和降序排序。列表使用服务器分页，每页默认 12 件。只显示正常卖家的在售商品。没有结果时可重置条件；请求失败时可重试。

首页推荐之外的集市列表始终尊重自己的搜索和筛选条件，搜索不会改变推荐偏好。分类名称和顺序由管理员配置。

## 3. 商品详情、收藏与咨询

详情展示 1–5 张图片、价格、成色、描述、卖家、状态、收藏和交易入口。点击卖家卡片进入其闲置小铺。收藏按钮支持取消收藏，重复点击不会生成重复记录；个人中心可查看收藏列表及商品当前状态。

登录后可在详情留言。只有卖家可以对某条咨询点击回复，回复显示原留言。留言保存在 MySQL，刷新仍在。自己的商品收到咨询、自己的留言被卖家回复时会生成站内通知。“留言消息”集中显示自己发出、自己的商品收到及回复本人的相关消息，最多最近 200 条。

留言是商品下的公开咨询，不是私聊，不应填写手机号、宿舍门牌等敏感信息。已售出或已下架商品不接受新留言。

## 4. 发布、编辑和下架

点击“发布闲置”，填写标题、启用分类、价格、成色、描述，上传 1–5 张 JPG/PNG 图片。每张输入最多 5MB，后端会检查实际图片内容、格式和像素大小，再重新编码保存；不能用任意外链或别人的上传路径冒充本人商品图片。

提交后为“待审核”，本人和管理员能查看，其他同学看不到。审核通过变为“在售中”；驳回会保留原因并通知卖家。卖家可以编辑补充后重新提交。

修改在售商品会重新进入审核，并取消该商品尚未被接受的预约。下架后不再公开展示，尚未接受的预约自动取消。预订中的商品须先取消交易再编辑或下架；已售出商品不能重新出售或修改。

| 商品状态 | 含义 | 卖家接下来能做什么 |
| --- | --- | --- |
| 待审核 | 等待管理员检查 | 编辑、下架 |
| 已驳回 | 审核未通过，有原因 | 补充后重新提交 |
| 在售中 | 正常公开，可预约 | 回复、接受预约、编辑、下架 |
| 已预订 | 已接受一位买家 | 面交，或取消该交易 |
| 已售出 | 买家已确认完成 | 查看成交记录与评价 |
| 已下架 | 不再公开 | 编辑后重新提交审核 |

停用分类不能用于新发布或重新提交；原有商品和订单保留，避免破坏历史记录。

## 5. 完整交易流程

### 5.1 买家发起预约

在他人在售商品的详情点击“我想要 · 发起交易”，确认后进入“我的购买”。这一步不付款，也不会立即独占商品。同一买家不能为同一商品重复建立未完成预约。

### 5.2 卖家接受或拒绝

卖家在“我的出售”点击“接受交易”。商品变为已预订，其他买家尚未确认的预约自动取消，并分别收到通知。也可拒绝预约或填写原因。

后端在事务中先锁商品再锁订单，数据库还对每件商品的已确认订单加唯一约束；多个请求竞争时最多一个能被接受。

### 5.3 线下交接和确认完成

接受后，通过商品留言约定校内公共场所与时间。买家收到并检查实物后点击“确认完成”；订单变为已完成，商品变为已售出。卖家和管理员不能代替买家确认。

待确认或已预订的订单均可由对应买卖双方取消，已预订订单取消后商品恢复在售。已完成或已取消的订单不能重复处理。管理员强制下架时，未完成订单会同步取消。

### 5.4 查看进度

“我的购买 / 我的出售”的每条记录都有“交易进度”，进入独立订单详情，查看当前步骤、商品价格快照、交易双方、操作按钮、事件时间线和评价。

时间线记录创建、卖家接受、取消、完成和评价；自动取消也会记录。线下交接没有独立电子签到，不能把界面步骤当作系统已验证实物交付；最终由买家确认。

旧版本没有记录卖家接受时间。升级时只导入已知的创建/完成时间，其他过程显示“升级前的订单状态……早期过程未记录”，不会伪造历史时间。

订单保存创建时的商品标题、图片路径和金额，后续状态改变不会覆盖这些快照。管理员可查看订单详情，但不能替交易双方确认或评价。

## 6. 卖家小铺和交易评价

从商品详情卖家卡片，或个人中心“查看我的小铺”进入。小铺公开展示昵称、头像、签名、加入时间、在售数量、完成交易数量、平均评分、评价数、在售商品和成交评价；商品和评价分别分页。

平均评分只根据真实已提交评价计算，保留一位小数。未被评价时显示“暂无成交评价”，不会给新卖家默认满分。完成交易数与评价数不同：买家可以暂不评价。

买家在已完成订单详情填写 1–5 星和 5–500 字评价。只有该订单的买家可以提交，每笔订单一次，后台及数据库共同防止重复。评价公开出现在卖家小铺；卖家收到通知。评价目前不提供修改、删除或卖家回评入口。

评价只代表交易者的反馈，不等同于学校认证或平台担保。页面不会公开账号密码、买家订单号等内部信息。

## 7. 站内通知

点击导航右侧铃铛进入，支持全部/只看未读、分页、逐条点击阅读、全部标为已读。点击通知跳转到对应商品、订单、举报记录或卖家页。用户只能读取和标记自己的通知。

| 触发事件 | 通知接收人 |
| --- | --- |
| 商品通过、驳回、管理员下架 | 卖家 |
| 商品收到咨询 | 卖家（本人留言不自通知） |
| 卖家回复咨询 | 原留言人 |
| 新建、接受、拒绝、取消、完成订单 | 对应买卖双方 |
| 商品变更导致预约自动取消 | 对应买卖双方 |
| 买家提交评价 | 卖家 |
| 举报处理完成 | 举报人 |

通知和业务变更在同一事务中保存。铃铛未读数在页面切换及约 30 秒轮询时刷新；通知页面支持主动刷新。这不是 WebSocket 实时推送，也不发送邮件或短信。升级前未保存的通知不会全部补发。

## 8. 个人中心和举报

“我的校园”包含我的发布、我的购买、我的出售、我的收藏、我的举报和个人资料。支持头像、昵称、签名修改；账号名不可在资料页修改，当前没有密码找回或修改密码入口。

商品详情右上角可举报，填写问题描述。相同用户对同一商品不能重复建立待处理举报。自己的举报记录显示处理结果与时间。管理员处理举报和下架商品是两个独立、有日志的操作，处理举报不自动删除商品。

## 9. 管理后台

管理员登录后导航出现“管理后台”。普通学生即使手动访问管理接口，也会被后端拒绝。

| 页面 | 能做什么 |
| --- | --- |
| 运营总览 | 累计用户、商品、待审核、已完成订单、成交额、待处理举报；区间趋势与分类分布 |
| 商品审核 | 按标题/状态查找，通过、驳回、强制下架；驳回/下架必须填写原因 |
| 用户管理 | 查询账号/昵称，禁用或恢复；管理员账号受保护 |
| 举报管理 | 按状态查找，标记处理或驳回，填写结果 |
| 订单管理 | 按状态、买卖方、创建日期查询，进入订单详情；不代替用户完成交易 |
| 分类管理 | 新增、改名、选图标、调整排序、启停；无商品引用时可删除 |
| 公告管理 | 新增、编辑、草稿/发布、置顶、删除；发布内容显示在首页 |
| 操作日志 | 查看管理员的对象、动作、说明和时间 |

上述管理列表均为服务器分页，默认每页 20 条。禁用学生会立即撤销已有会话，其商品不再公开；有待线下交易的账号需先完成或取消交易，再执行禁用，防止订单悬空。分类关联过商品时不能直接删除，可停用保留历史。

### 统计口径

顶部卡片为累计数据，不随日期选择变化。区间默认近 7 天，可选 1–90 天。

- 趋势、区间成交笔数与金额：按北京时间的订单完成日期，仅计已完成订单。
- 发起预约及其当前状态：按订单创建日期。
- “区间创建的预约中已有多少完成”：该创建区间订单目前的状态，不能与完成日期区间混算转化率。
- 分类分布：累计所有状态商品，包含待审核、已售出等，非当前在售占比。
- 空区间显示零和补齐日期的趋势，不生成虚假数据。

## 11. 建议演示顺序

准备卖家、买家、管理员三个独立浏览器窗口或无痕上下文，避免同一个标签页互相覆盖登录。

1. 访客查看首页、公告、搜索与卖家小铺。
2. 卖家上传本人拍摄的商品图片并发布，展示待审核私有状态。
3. 管理员通过审核，卖家收到通知，首页出现该商品。
4. 买家收藏相近商品，回到首页展示推荐理由，再留言、预约。
5. 卖家回复并接受，展示订单进度；其他竞争预约自动取消。
6. 买家确认完成，写评价；卖家小铺评分与评价更新。
7. 管理员查看订单和统计变化，维护一条公告或分类。

提交录屏建议围绕一件商品完成流程；不要展示本机真实密码。初始插画仅供启动演示，正式录屏可由卖家上传实物照片。没有更改技术栈，不需要重新学习另一套后端框架。
